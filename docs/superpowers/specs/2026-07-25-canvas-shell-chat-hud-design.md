# zeroxB 永久画布、文本侧栏与 AI 对话 HUD 设计

日期：2026-07-25
状态：正式规格 v1，待用户审阅
适用平台：Windows 桌面端

## 1. 背景

zeroxB 目前在画布激活时进入一套沉浸布局：中央可以绘制画布，底部可以输入 AI 问题，但原有的左侧文件/笔记/画布栏、右侧编辑区域、聊天标题、消息记录和会话历史都被隐藏。结果是画布像一个临时窗口，用户能提问却看不到上下文，也不能自然地在笔记、画布和 AI 之间往返。

现有程序已经具备以下可复用能力：

- 文件、文本笔记和画布三个左侧栏目及其操作。
- 文本编辑器的多标签、保存、历史和预览能力。
- 聊天数据库、全局会话、消息列表、会话搜索、删除、新建和 RAG/Agent 展示。
- 麦克风输入、TTS 朗读、每条消息的手动朗读和 AI 处理中状态。

本设计不重做这些底层能力，而是把它们重新组织为“永久画布工作台”：画布始终是中央主工作区，左侧负责浏览和拖入，右侧负责深度阅读，底部负责 AI 对话。当前会话文字显示在跟随对话坞的屏幕空间 HUD 中，保持轻量而不污染画布数据。

本设计依赖并必须遵守：

- 《zeroxB 视角归一化内容尺寸设计》：屏幕—画布换算、操作快照、内容尺寸兼容。
- 《zeroxB 实体区块碰撞与选中视觉设计》：实体范围、碰撞、最近空位、关联节点和视觉状态。

## 2. 目标

1. 首页中央永久挂载画布，不因打开文本、切换侧栏或切换 AI 会话而卸载。
2. 保留文件、文本笔记和画布的原有浏览功能，并允许侧栏折叠。
3. 笔记可以预览、正常打开编辑，也可以拖入画布形成可同步的关联节点。
4. 右侧文本面板保留多标签能力，打开文本时画布仍然可见。
5. 全局 AI 会话可以跨画布保留，但每条消息标记来源画布，发送时的画布知识库范围明确。
6. 当前会话记录直接以屏幕空间文字 HUD 显示在底部对话坞上方，不跟随画布平移或缩放。
7. 对话坞可收缩、展开、滚动、搜索历史，并保留 TTS/STT 与原有 AI 权限模式。
8. UI 状态、聊天内容和笔记引用不写入画布文档，保持画布数据边界清晰。

## 3. 非目标

- 不替换现有聊天数据库、会话模型、RAG、Agent 执行器或 TTS/STT 引擎。
- 不把聊天消息变成画布实体、关系线或可拖动节点。
- 不复制笔记正文到画布节点；正文只有一个文本页来源。
- 不把右侧文本面板改成新的编辑器，不删除现有多标签、历史和文件处理能力。
- 不改变实体区块的无嵌入、无重叠、碰撞和撤销语义。
- 不改变右键框选、右键关系创建、中键平移、层级调整、AI 编辑/管理权限和现有撤销重做语义。
- 不增加常驻的聊天全屏面板、迷你地图或新的信息侧栏。
- 不在本任务中添加移动端布局。
- 不修改用户的本机 AI 配置或读取、输出 API 密钥。

## 4. 术语与依赖约束

### 4.1 永久画布工作台

永久画布工作台是首页唯一的中央主容器。它可以被左右面板遮挡或缩小，但不会被文本页面或聊天页面替换，也不会因为面板变化重新初始化 React Flow、画布文档或视角。

### 4.2 屏幕空间 HUD

HUD 是挂在应用窗口层的界面内容，不属于 React Flow 画布层：

- 不使用画布坐标。
- 不参与画布平移、缩放、框选、碰撞、关系避障或导出。
- 不保存进 `CanvasDocument`，不进入画布撤销栈。
- 随底部对话坞的屏幕位置和展开状态变化。
- 滚轮在 HUD 内滚动聊天，离开 HUD 后交还画布缩放。

### 4.3 关联节点

关联节点是实体区块规格中的一种内容卡片，保存源笔记稳定 ID 和可刷新的展示摘要；它不保存源正文。关联节点可以在一个画布中出现多次，每个引用拥有独立位置、尺寸、标签和关系。

## 5. 永久画布工作台布局

### 5.1 区域结构

窗口从左到右由三类区域构成：

```text
┌──────────────┬──────────────────────────────┬──────────────────┐
│ 可折叠左侧栏 │ 永久中央画布                 │ 可折叠文本面板   │
│ 文件/笔记/画布│ 点阵、区块、关系、AI HUD      │ 多标签文本编辑   │
└──────────────┴──────────────────────────────┴──────────────────┘
                         ▲
                    底部 AI 对话坞
```

- 左侧栏展开默认 `320px`，可调整范围为 `280–420px`，折叠后保留 `48px` 图标栏。
- 右侧文本面板默认 `420px`，最小 `360px`，最大不超过窗口宽度的 `55%`；支持拖动分隔线和一键折叠。
- 中央画布始终占据剩余空间，至少保留现有画布操作的最小可用宽度。
- 左右面板宽度、折叠状态和当前左侧栏目写入界面偏好；不写入画布文档。
- 面板打开、关闭或调整时，画布保留节点、视角、选择、关系预览和当前临时状态；只重新计算可见容器尺寸。

### 5.2 页面与标签规则

- 画布项目不再作为普通编辑器标签替换中央页面；点击左侧画布项目只切换当前永久画布。
- 文本、Markdown 和其他已有编辑器页面在右侧面板中打开；现有编辑器标签栏继续工作。
- `activeCanvasId` 与右侧 `activeDocumentTabId` 是独立状态；打开、关闭或切换文档标签不得修改当前画布，切换画布也不得关闭文档标签。
- 右侧面板关闭时不关闭内部标签；再次打开恢复上次打开的标签和滚动位置。
- 如果用户通过现有文件功能打开非文本文件，继续使用原有文件查看/编辑能力，但仍不卸载中央画布。
- 左侧栏和右侧面板同时折叠时，中央画布扩展到整个工作区；AI 对话坞仍相对于可见画布区域居中。

## 6. 左侧栏、预览与笔记拖动

### 6.1 三个原有栏目

左侧栏保留当前三个栏目及原有操作入口：

- 文件：文件树、文件操作、拖放和现有筛选。
- 文本笔记：笔记列表、搜索、标签、预览和编辑入口。
- 画布：画布项目列表、新建、删除、重命名、切换和现有管理操作。

折叠后每个栏目仍有可访问图标、悬停提示和键盘焦点。展开/折叠按钮不改变当前栏目和滚动位置。

### 6.2 悬停预览

- 鼠标在文本笔记条目上停留 `400ms` 后显示只读预览。
- 预览浮层位于左侧栏和画布之间，不改变三栏尺寸。
- 浮层包含标题、更新时间、截断正文和“打开”提示，不显示完整编辑控件。
- 光标从条目移动到预览浮层时，预览保持；离开条目和预览区域后延迟 `160ms` 关闭。
- 预览不创建编辑器标签、不修改阅读进度、不写历史。
- 开始拖动条目时立即关闭预览并抑制本次拖动的单击打开行为。

### 6.3 单击、拖动与双击

- 单击笔记条目：在右侧文本面板打开对应原文，并切换到已有标签或新建一个标签。
- 拖动笔记条目到中央画布：创建一个关联节点预览；落点执行实体区块规格的 6px 间距、吸附、碰撞和最近空位算法。
- 双击关联节点：在右侧文本面板打开同一个源笔记，并在文本页可正常编辑。
- 拖动未完成、目标无合法空位、源笔记读取失败时不创建空节点、不删除源笔记、不写历史。
- 左侧栏拖动创建的节点不复制正文，源笔记仍可正常在文本页中浏览和编辑。

## 7. 右侧文本面板与关联引用

### 7.1 面板行为

- 右侧面板使用现有编辑器布局和多标签栏，不重新实现文本编辑器。
- 同时打开多篇笔记时，每篇笔记拥有独立标签、滚动位置和编辑状态。
- 文本自动保存、历史、搜索、文件关联、Markdown 渲染和其他现有功能保持不变。
- 右侧面板中的“关闭”只关闭面板可见性；标签在内存和现有编辑器状态中保留。
- 右侧面板打开时，画布依然响应中键平移、画布缩放和不被面板覆盖的节点操作。

### 7.2 关联节点数据

关联节点至少保存：

```ts
interface NoteReferenceData {
  sourceNoteId: string
  sourceTitle: string
  sourceExcerpt: string
  sourceUpdatedAt: number
  sourceStatus: 'available' | 'missing'
}
```

- `sourceNoteId` 是唯一关联依据，不使用标题或路径作为主键。
- `sourceTitle`、`sourceExcerpt` 和 `sourceUpdatedAt` 是最近一次同步的展示缓存，不是正文副本。
- 同一笔记可以在同一画布中创建多个引用；每个节点的画布位置、尺寸、标签、颜色和关系独立保存。
- 原笔记内容、标题或更新时间改变后，所有对应引用节点自动刷新缓存。
- 刷新失败保留上一次可用缓存并显示轻量同步状态，不清空节点。
- 原笔记删除或不可访问时，所有引用进入 `missing` 状态，显示“来源已不存在”；用户可以重新关联或删除引用。
- 删除引用只删除节点和其关系，不删除源笔记或其他引用。

## 8. 全局 AI 会话与来源画布

### 8.1 全局会话

会话继续使用现有全局会话数据库，不按画布拆成多套数据库。会话列表包含所有画布来源的会话，支持已有置顶、搜索、排序、删除、新建和临时会话能力。

每条用户或 AI 消息补充来源上下文：

```ts
interface CanvasChatContext {
  sourceCanvasId: string | null
  sourceCanvasTitle: string | null
  sourceNodeIds?: string[]
  sentAt: number
}
```

- 发送消息时记录当前画布 ID、标题快照和时间。
- AI 回答继承该请求的来源画布上下文；如果 AI 工具定位了区块，可记录 `sourceNodeIds`。
- 画布重命名后，历史消息保留标题快照，同时通过 ID 尝试显示最新标题。
- 画布删除后消息仍保留，来源标记显示“画布已不存在”，不删除聊天记录。
- 旧聊天消息缺少来源字段时按 `sourceCanvasId: null` 兼容读取，显示为“来源未记录”；数据库迁移不得删除、复制或重排旧消息。

### 8.2 当前画布知识库边界

- 每次发送请求时，以当时可见的当前画布作为唯一画布 RAG 知识库。
- 全局会话之前来自其他画布的消息可以作为对话上下文，但不能把其他画布节点自动注入本次画布检索结果。
- AI 需要跨画布查询时必须明确得到用户指令，并使用已有全局会话/搜索能力；默认不跨画布检索。
- 当前 AI 编辑模式、管理模式、操作预览、审批和回退权限全部沿用既有规则；HUD 不改变权限边界。

### 8.3 来源标记与跳转

- 当前画布产生的消息默认不显示冗余来源标签。
- 当前聊天中来自其他画布的消息旁显示低调的画布名称标记。
- 点击来源标记时切换到对应画布；画布存在且消息带 `sourceNodeIds` 时，使用已有画布聚焦能力定位相关区块。
- 来源画布不存在时只显示状态提示，不阻塞继续聊天。

## 9. AI 对话坞与屏幕空间 HUD

### 9.1 收缩状态

底部对话坞保持现有输入功能和 Stitch/Siri 风格：

- 输入框、发送、麦克风、历史、新建会话、模型/权限入口继续使用现有组件能力。
- 对话坞上方显示最近一轮原文：用户问题最多一行，AI 回答最多三行。
- 截断只使用确定性的行数和字符宽度，不额外调用模型生成摘要。
- 文字上缘使用渐隐，保持画布内容可见；AI 处理时与现有呼吸提示同步。
- 点击摘要、展开按钮或向上拖动展开完整 HUD。
- `Esc`、向下拖动或再次点击展开按钮收缩 HUD，不丢失滚动位置。

### 9.2 展开状态

- 当前会话消息从对话坞向上展开，最大高度为可见画布区域的 `42%`，并设置 `560px` 硬上限。
- HUD 使用透明渐变和局部背景模糊，不绘制覆盖整块画布的厚重卡片。
- 消息内容复用现有 `ChatContent` 的 Markdown、思考、Agent、RAG、MCP、附件、删除和消息控制渲染能力。
- HUD 始终使用屏幕坐标，画布平移、缩放和视角跳转不会移动消息文字。
- HUD 内滚轮只滚动聊天；鼠标离开 HUD 后滚轮恢复画布缩放。
- 正在生成时显示加载/流式状态；收缩 HUD 仍显示呼吸提示和最新片段。
- 当前会话为空时显示轻量提示和示例问题，不显示空白大面板。

### 9.3 历史浮层

- 历史按钮在对话坞上方打开宽 `360px`、最大高 `420px` 的可搜索浮层。
- 浮层支持标题搜索、置顶排序、更新时间排序、切换、删除、新建和临时会话。
- 选择会话后浮层关闭，HUD 切换到所选会话；不会改变画布节点或右侧文本标签。
- 点击画布空白、点击对话坞外部或按 `Esc` 关闭浮层。
- 当前回答生成中禁止无提示切换；用户选择切换时先停止生成或明确要求确认。
- 历史浮层不常驻，不占用左侧文件/笔记/画布栏，也不成为画布节点。

### 9.4 HUD 状态持久化

- 收缩/展开、HUD 滚动位置和历史浮层打开状态是界面状态，不写入画布文档。
- 收缩状态在本次应用会话内保留；应用重启默认收缩，避免遮挡初始画布。
- 当前会话 ID继续由现有聊天 store 管理；画布切换不清空全局会话。
- HUD 状态不能覆盖或改变现有会话的数据库内容。

## 10. 语音与 TTS

- 普通文字提问默认不自动朗读；每条 AI 消息保留现有扬声器按钮，可播放、暂停或停止。
- 麦克风提问进入语音会话状态；最终 AI 回答完成后自动朗读。
- 流式生成过程中不逐字朗读，等待最终回答完成，避免断句和重复播放。
- 用户再次开始说话、切换会话、切换画布、收缩 HUD 或关闭对话坞时停止当前朗读。
- TTS 不可用、网络/模型失败或语音被系统中断时，保留完整文字回答并显示轻量提示。
- STT 结果先填入输入框，保留用户确认和编辑后再发送的现有语义；不因 HUD 收缩而自动发送。
- TTS/STT 控件的加载、播放、停止和错误状态与呼吸提示同处于对话坞，不新增语音面板。

## 11. 状态、错误与恢复

### 11.1 画布与面板

- 画布初始化失败时保留现有错误处理，并显示可重试入口；左侧栏和 AI 输入不伪造成功状态。
- 右侧文本面板加载失败时保留源条目，显示错误状态；不创建空标签或丢失其他标签。
- 面板尺寸、折叠和画布容器发生变化时，重新计算 HUD 可视高度，但不重置聊天滚动或画布视角。

### 11.2 聊天与历史

- 聊天数据库加载失败时显示可重试的轻量错误，输入框仍可保持禁用状态，不能把未保存消息误显示为历史记录。
- AI 流式请求失败时保留已生成文字和错误状态；用户可以重试，不自动复制或重复写入消息。
- 切换会话/画布时保存当前输入草稿到现有会话 UI 状态，不把未发送文字写入聊天历史。
- TTS 失败不删除回答；手动播放仍可重试。

### 11.3 笔记引用

- 预览读取失败不阻塞打开或拖动；拖动失败不产生半成品节点。
- 关联节点刷新失败保留旧缓存并记录脱敏诊断。
- 源笔记删除只让引用进入缺失状态，用户显式选择后才删除引用。

## 12. 可访问性与交互反馈

- 折叠侧栏图标、展开按钮、历史按钮、麦克风和 TTS 按钮提供明确的 `aria-label` 与键盘焦点。
- 预览不能只依赖悬停：键盘聚焦笔记条目时同样在 `400ms` 后显示预览，`Enter` 打开文本页。
- HUD 的展开、收缩、历史浮层和右侧面板都支持 `Esc` 退出和可见焦点环。
- HUD 文字层与画布之间保持足够对比；文字渐隐不能影响最后一行阅读。
- 自动朗读提供可见播放状态，并允许键盘停止。
- 侧栏、右侧文本面板和 HUD 在窗口宽度较小时按顺序收缩，保证输入框、画布基本操作和关闭按钮不被裁切。

## 13. 性能与模块边界

### 13.1 应用壳层

`page.tsx`/应用壳层负责永久挂载画布、协调左侧栏、中央画布、右侧面板和底部 HUD；不直接解析聊天消息或笔记正文。

### 13.2 左侧栏与文本面板

`left-sidebar.tsx` 保留栏目和动作；笔记列表负责预览/拖动事件；`editor-layout.tsx` 继续提供右侧多标签文本编辑。关联节点创建只通过现有画布事件编排和实体落点策略提交。

### 13.3 AI HUD

新增或调整独立 HUD 壳层，负责收缩/展开、屏幕定位、滚动、历史浮层和来源标记；消息内容优先复用现有 `ChatContent`、`ChatHeader`、`ChatInput`、`ChatFooter` 和消息控制组件。

HUD 不直接读取数据库；通过现有 `useChatStore` 读取当前会话、消息、加载、Agent 和语音状态。会话来源画布元数据由聊天 store/数据库边界维护，具体字段迁移须在实现计划中单独拆任务。

### 13.4 性能规则

- 画布永久挂载时不得因 HUD 消息更新而重新创建 React Flow 实例或重算全部节点。
- HUD 消息列表使用现有消息滚动和必要的虚拟化/分段渲染；长会话初始只挂载可见内容。
- 笔记预览只加载标题、摘要和必要缩略内容；不因鼠标移动读取整篇全文。
- 关联节点同步按源笔记 ID 批量刷新，不为每个引用重复扫描整个画布。
- 侧栏折叠、面板调整和 HUD 展开只更新对应区域，不触发全局聊天/画布重载。

## 14. 验证设计

### 14.1 壳层与画布

- 画布模式始终挂载中央画布；切换左侧栏目、右侧文本标签、HUD 会话和面板尺寸不会丢失画布状态。
- 左侧栏展开/折叠恢复 `320px`/`48px` 状态，栏目和滚动位置保持。
- 右侧文本面板打开、调整、折叠和重开保持多标签、滚动和编辑状态。
- 左右面板同时折叠时画布占满可见区域，HUD 重新居中。

### 14.2 笔记预览与关联节点

- 悬停/键盘聚焦 400ms 显示预览，进入预览浮层不会过早关闭。
- 单击打开右侧文本页，拖动创建关联节点，三者不误触。
- 同一源笔记可创建多个引用；源笔记更新后所有引用同步标题、摘要和时间。
- 删除引用不影响源笔记；删除源笔记后所有引用显示缺失状态。
- 拖入位置被占用时按实体碰撞规格寻找合法空位，失败不写空节点。

### 14.3 全局会话与 HUD

- 普通文字提问和麦克风提问写入同一全局会话体系。
- 每条消息保存来源画布；切换画布后旧消息标记和新请求检索范围正确。
- HUD 收缩显示最近一轮原文截断，展开显示完整当前会话并可滚动。
- 画布平移、缩放、右侧文本面板变化不会移动 HUD 文字。
- 历史浮层可搜索、切换、删除和新建；生成中切换有明确停止/确认。
- HUD 内滚轮不缩放画布，HUD 外滚轮继续缩放画布。

### 14.4 TTS/STT 与安全控制

- 文字提问不自动播放；麦克风提问的最终回答自动播放。
- 再次说话、切换会话/画布、收缩或关闭 HUD 时停止播放。
- 流式回答等待完成后只朗读一次；TTS 失败保留文字。
- AI 编辑/管理模式、审批、预览、撤销和回退规则不因 HUD 改变。

### 14.5 集成与 Windows 验证

- Canvas 测试、聊天/会话 store 测试、关联节点测试、TypeScript、生产构建和锁定 Cargo 检查通过。
- Windows 安装版验证永久画布、侧栏折叠、文本拖入、右侧多标签、HUD 记录、历史切换和 TTS。
- 现有点阵背景、实体碰撞、右键手势、中键平移、关系线、AI 对话和线性浏览无回归。

## 15. 验收标准

1. 首页始终显示并保留中央画布，画布不会因打开文本或聊天而变成普通窗口。
2. 左侧文件、文本笔记、画布栏目保留，可折叠为图标栏并恢复状态。
3. 笔记悬停可预览、单击可在右侧多标签文本页浏览编辑、拖动可创建关联节点。
4. 同一笔记可在一个画布中拥有多个引用；正文单一来源，所有引用自动刷新展示缓存。
5. 右侧文本面板关闭后不丢失标签，画布仍可见和可操作。
6. 全局会话保留现有历史能力，每条消息有来源画布，发送时检索只使用当前画布。
7. 当前会话以屏幕空间 HUD 跟随底部对话坞，收缩显示最近一轮，展开显示完整记录。
8. 历史按钮打开可搜索浮层，切换会话不会丢失画布、文本标签或未确认的安全状态。
9. TTS/STT、自动朗读、手动朗读、停止和错误回退符合第 10 节。
10. HUD、侧栏和文本面板不写入画布文档，不参与画布平移、缩放、碰撞或撤销。
11. 现有编辑/管理权限、文件、关系、点阵、碰撞、撤销和 Windows 安装功能不回归。
12. 自动化验证和 Windows 安装版实机验证全部通过。
