# zeroxB 视角归一化内容尺寸设计

日期：2026-07-25  
状态：正式规格 v1，待用户审阅  
适用平台：Windows 桌面端

## 1. 背景

zeroxB 使用无限画布承载文本、图片、文件、链接和其他媒体。当前画布已经支持缩放、拖动绘制区块、粘贴和拖入内容，但不同入口采用固定画布尺寸：

- 新画布默认视角为 100%。
- 底部缩放控件当前范围为 25%–200%。
- 文本字号仅支持 13、15、18 和 24 四个固定画布字号。
- 粘贴和拖入的链接、文件及图片使用固定的 320px 宽度预设。

当用户在远景或高倍率视角下直接创建内容时，固定画布尺寸无法对应用户当时看到和操作的屏幕尺寸。本设计引入“视角归一化创建”：用户以屏幕上的观感尺寸进行创建和编辑，zeroxB 在操作开始时捕获当前视角倍率，并将屏幕尺寸换算为稳定的画布实际尺寸。

## 2. 目标

1. 用户在 10%–600% 的任意画布倍率下都能直接创建和编辑尺寸可预测的区块、文字、图片和媒体卡片。
2. 用户鼠标拖出的屏幕面积，就是创建瞬间看到的区块面积。
3. 字号菜单显示当前视角下的屏幕观感字号，而画布保存换算后的实际字号。
4. 创建完成后，内容尺寸固定；后续缩放画布不会反复改写已有数据。
5. 所有用户直接创建入口使用同一套换算规则。
6. AI 创建内容不依赖当前镜头倍率，而是匹配关联或附近内容的尺度。
7. 现有画布无需迁移，已有区块、字号和媒体尺寸不被重写。

## 3. 非目标

- 本功能不新增富文本编辑器，也不改变现有区块内容类型。
- 本功能不让文字或图片在每次画布缩放时保持固定屏幕大小。
- 本功能不自动重排、放大或缩小已有区块。
- 本功能不改变中键平移、右键框选、关系创建和关系编辑手势。
- 本功能不让 AI 在 10% 总览视角下按镜头倍率生成巨型区块。
- 本功能不修改用户的本机 AI 配置或读取、输出 API 密钥。

## 4. 已确认产品决策

### 4.1 画布视角范围

- 新画布初始缩放倍率：65%，即 `0.65`。
- 最小缩放倍率：10%，即 `0.10`。
- 最大缩放倍率：600%，即 `6.00`。
- 有效保存视角要求 `x`、`y` 和 `zoom` 都是有限数，且 `zoom > 0`。
- 有效视角的 `x` 和 `y` 原样保留；`zoom` 在 0.10–6.00 内原样保留，低于 0.10 时按 0.10 打开，高于 6.00 时按 6.00 打开。
- `x` 或 `y` 无效时该坐标按 `0` 打开；`zoom` 缺失、非有限或小于等于零时按 0.65 打开。
- 载入时的兼容归一化只作用于内存，不立即重写文档；用户随后正常移动视角并触发现有视角持久化时再保存规范值。
- “适应画布”仍可自动计算视角，但结果必须限制在 10%–600% 之间。

### 4.2 创建时换算

设：

- `Z` 为操作开始时捕获的画布缩放倍率。
- `S` 为用户在屏幕上看到或指定的尺寸。
- `C` 为持久化到画布中的实际尺寸。

统一换算公式：

```text
C = round4(S / Z)
S = round2(C × Z)
```

`round4` 用于持久化，表示四舍五入到四位小数；`round2` 仅用于界面显示，表示四舍五入到两位小数。两者都把 `-0` 归一化为 `0`。使用四位持久化精度可以保证在 600% 极端倍率下完成一次正向和反向换算后，屏幕误差不超过 0.01px。

示例：

| 当前视角 | 屏幕目标字号 | 保存的画布字号 | 屏幕绘制宽度 | 保存的画布宽度 |
|---:|---:|---:|---:|---:|
| 10% | 15px | 150px | 300px | 3000px |
| 25% | 15px | 60px | 300px | 1200px |
| 65% | 15px | 23.0769px | 300px | 461.5385px |
| 100% | 15px | 15px | 300px | 300px |
| 200% | 15px | 7.5px | 300px | 150px |
| 600% | 15px | 2.5px | 300px | 50px |

这种差异是产品预期：用户在不同视角下创建的内容具有不同的真实画布尺度。回到同一视角比较时，它们会体现真实大小差异。

### 4.3 操作倍率快照

操作开始时捕获完整的 `ViewportSnapshot`：

```ts
interface ViewportSnapshot {
  viewportX: number
  viewportY: number
  zoom: number
  containerLeft: number
  containerTop: number
}
```

屏幕点转换为画布点：

```text
canvasX = round4((screenX - containerLeft - viewportX) / zoom)
canvasY = round4((screenY - containerTop - viewportY) / zoom)
```

- 鼠标按下开始绘制区块时捕获一次完整快照。
- 粘贴、拖入、节点文件选择或打开尺寸编辑会话时，在任何异步文件操作开始前捕获一次完整快照。
- 同一次操作始终使用捕获值，不读取中途变化的实时平移或缩放。
- 用户在创建或编辑过程中滚轮缩放，当前对象的尺寸不会跳变。
- 用户在异步文件持久化期间平移或缩放，最终节点仍落在操作开始时确定的画布位置。
- 操作结束或取消后丢弃原始快照，不持久化 `creationViewport`。
- 为了让卡片图标、内边距和图文间距保持创建时的屏幕观感，所有用户直接创建的新节点必须保存派生后的 `contentScale = round4(1 / Z)`。它是已经固化的画布内容尺度，不是后续会随镜头变化的操作快照。
- `contentScale` 的有效范围为 `0.1667–10`；旧节点缺少该值时使用 `1`。

## 5. 用户直接创建

“用户直接创建”包括：

- 在空白画布左键二维拖动绘制文本区块。
- 从剪贴板粘贴纯文本、网页链接、图片和普通文件。
- 从系统拖入纯文本、URI、HTML、图片和普通文件。
- 通过笔记选择器或图片选择器创建新节点。

以下操作不属于新内容视角换算：

- 导入完整的 zeroxB 画布 JSON、项目文件或 Mermaid 并替换当前文档。
- 复制、重复或粘贴 zeroxB 内部已有节点。
- 打开历史快照、同步数据或载入模板。

“完整画布导入”只由明确的“导入并替换当前画布”命令触发，不根据文件扩展名或内容自动推断。通过普通 paste、drop 或内容选择器进入画布的 JSON、zeroxB 项目文件、Mermaid 文件及 Mermaid 文本仍按普通文件或纯文本摄取，创建新节点并执行视角换算，不替换当前文档。只有用户主动调用完整画布导入命令后，导入器才解析并替换文档，同时保留源文档中的画布尺寸。

### 5.1 入口与内容类型矩阵

| 入口 | 支持内容 | 解析优先级 | 快照时机 | 尺寸处理 |
|---|---|---|---|---|
| 左键二维拖动 | 新文本区块 | 不适用 | 指针按下 | 使用屏幕拖动面积 |
| 剪贴板粘贴 | 文件、URI、HTML、纯文本 | 文件 → `text/uri-list` → `text/html` → `text/plain` | 收到 paste 事件后、异步处理前 | 使用屏幕预设 |
| 系统拖入 | 文件、URI、HTML、纯文本 | 文件 → `text/uri-list` → `text/html` → `text/plain` | 收到 drop 事件后、异步处理前 | 使用屏幕预设 |
| 笔记选择器 | 笔记节点 | 不适用 | 用户确认选择时 | 使用对应卡片屏幕预设 |
| 图片选择器 | 图片节点 | 不适用 | 打开文件对话框前 | 使用图片屏幕预设 |
| 内部复制/重复 | 已有节点和关系 | 不适用 | 尺寸换算不捕获；碰撞落点可按实体区块碰撞规格捕获 | 原样保留画布尺寸 |
| 完整画布导入 | JSON、项目文件、Mermaid | 不适用 | 不捕获 | 保留导入文档尺寸 |

`text/uri-list` 的解析规则：

- 忽略以 `#` 开头的注释行和空行。
- 取第一个合法的 `http://` 或 `https://` URI 创建链接卡片。
- 没有合法 URI 时继续尝试后续 HTML 或纯文本载荷。
- HTML 转换为纯文本后，如果完整内容恰好是一个 HTTP(S) URI，则创建链接卡片；否则创建文本区块。
- 本功能不从 HTML 下载远程图片，也不新增视频内容类型；不属于现有图片类型的媒体文件继续创建普通文件卡片。

### 5.2 鼠标绘制区块

- 是否形成有效区块继续按屏幕像素判断，而不是按画布坐标判断。
- 横向和纵向都至少达到现有有效面积阈值时才创建。
- 单击、轻微抖动和单轴拖动继续不创建区块。
- 屏幕拖动宽高分别除以捕获的 `Z`，保存为画布宽高。
- 区块位置和尺寸都使用同一个视角快照计算。
- 不重新引入 120×72 的固定最小区块尺寸。

### 5.3 粘贴与拖入文本

`estimateTextBlockSize` 继续根据文本长度估算 240–520px 的阅读宽度和对应高度，但这些数值改为“屏幕预设尺寸”：

1. 先在屏幕尺度估算区块宽高。
2. 再分别除以粘贴瞬间捕获的 `Z`。
3. 默认屏幕观感字号为 15px，并按同一 `Z` 换算。
4. 多项摄取的布局由《zeroxB 实体区块碰撞与选中视觉设计》接管，使用 6px 屏幕间距的无重叠纵向排列；本规格只负责按同一 `Z` 换算该间距。

### 5.4 链接、文件和媒体卡片

保留当前屏幕预设：

- 链接卡片：320×112px。
- 文件卡片：320×112px。
- 图片卡片：320×220px。

预设值在创建时除以 `Z` 后保存。卡片内部默认字号单独保存为换算后的实际字号；图标尺寸、内边距和图文间距通过节点的 `contentScale = round4(1 / Z)` 渲染，避免只放大外框而内部内容仍然过小。

### 5.5 图片

- 默认图片卡片继续保持 320×220px 的屏幕目标尺寸。
- 图片本身保持原始纵横比，不因换算发生拉伸。
- 用户通过图片调整手柄改变屏幕目标宽高时，使用调整开始时的完整视角快照计算画布尺寸。
- 无法读取图片尺寸时使用默认屏幕预设，不阻塞其他拖入内容。
- 复制已有图片区块时保留其画布尺寸，不按当前视角重新计算。

## 6. 文本字号编辑

### 6.1 显示值

字号控件显示屏幕观感字号：

```text
显示字号 = round2(画布实际字号 × 编辑会话倍率)
```

例如实际字号为 60px，在 25% 视角打开样式菜单时显示 15px。

### 6.2 修改值

用户把显示字号设置为 `P` 后：

```text
保存字号 = round4(P / 编辑会话倍率)
```

- 样式菜单打开时捕获编辑会话倍率。
- 菜单关闭前的所有字号修改使用该快照。
- 仅打开并关闭菜单不会写入新字号。
- 只有用户实际修改时才建立历史快照并保存。
- 屏幕观感字号允许 8–96px。
- 保留“小 13 / 标准 15 / 大 18 / 标题 24”快捷项，同时提供 8–96px 的连续数值输入。
- 多选区块字号不一致时显示“混合”；用户输入新值后，各区块按同一屏幕观感字号换算。
- 8–96px 只限制用户新提交的屏幕观感字号，不限制从已有画布实际字号计算出的显示值。计算结果即使小于 8px 或大于 96px，也按公式原样显示且不得自动截断、改写节点或建立历史。
- 当当前显示值超出 8–96px 时，数值输入仍显示该真实值；用户选择快捷项或提交一个范围内的新值后再执行换算。用户提交非有限值或范围外值时保留原字号、显示校验提示且不建立历史。

### 6.3 持久化类型

`CanvasNodeData.fontSize` 从固定联合类型放宽为有限数字：

- 持久化允许整数或最多四位小数，界面显示最多两位小数。
- 非有限数、零和负数不写入。
- 旧画布中的 13、15、18 和 24 无需迁移。
- 渲染仍直接使用持久化的画布实际字号。

## 7. 区块调整与已有内容

- React Flow 的区块缩放手柄在调整开始时捕获完整视角快照，并使用“屏幕指针增量 ÷ 快照倍率”计算画布宽高。
- 调整外框大小不会自动改变已有文字、图片、内边距或图文间距。
- 如需同时缩放内部内容，应由未来独立的“整体缩放内容”功能处理，不混入本功能。
- 复制和复制粘贴已有区块时保留其画布实际尺寸。
- 撤销、重做、同步、导入旧画布和打开历史快照时不执行视角换算。
- 只有“从屏幕操作创建新内容”或“用户明确修改屏幕观感尺寸”才执行换算。

### 7.1 尺寸编辑操作矩阵

| 操作 | 快照时机 | 画布结果 | 比例规则 | 取消/异常 | 历史边界 |
|---|---|---|---|---|---|
| 新建文本区块 | 指针按下 | 屏幕矩形除以快照倍率 | 宽高独立 | 无有效面积或 pointer cancel 时不创建 | 成功释放后一次 |
| 调整文本/文件/链接外框 | 调整手柄按下 | 初始画布尺寸加屏幕增量除以快照倍率 | 宽高独立 | pointer cancel、失焦或捕获丢失时恢复初始尺寸 | 成功释放后一次 |
| 调整图片区块 | 调整手柄按下 | 初始画布尺寸加屏幕增量除以快照倍率 | 默认锁定原始纵横比 | pointer cancel、失焦或捕获丢失时恢复初始尺寸 | 成功释放后一次 |
| 插入图片 | 文件选择或 drop/paste 事件 | 320×220 屏幕预设除以快照倍率 | 保持原图比例，外框使用等比 contain | 文件失败时不创建 | 成功节点批次一次 |
| 修改屏幕字号 | 打开样式菜单 | 用户观感字号除以会话倍率 | 不适用 | 非法输入保留原值 | 会话第一次有效修改前一次 |

本功能不新增区块宽高或图片宽高的数字输入框。区块和图片尺寸编辑通过现有调整手柄完成；字号继续提供快捷项和连续数值输入。

尺寸调整采用本地事务：

1. 开始时保存节点的会话前尺寸，但不立即写入撤销栈。
2. 拖动期间可以预览临时尺寸。
3. 成功 pointer up 时，把会话前快照写入撤销栈一次，再提交最终尺寸。
4. pointer cancel、窗口失焦或捕获丢失时恢复会话前尺寸，不产生历史记录。

样式菜单属于实时提交控件，没有“取消”按钮。仅打开和关闭不产生历史；第一次有效修改前写入一次会话前快照，后续修改继续复用该历史边界，关闭菜单后保留结果，用户可以通过撤销恢复。

## 8. AI 创建尺度

AI 创建不使用当前镜头倍率。尺度选择顺序如下：

1. AI 操作如果引用了同类型目标区块，优先逐字段使用目标区块的有效尺寸。
2. 目标类型不同、目标字段无效或没有明确目标时，从附近同类区块逐字段计算参考值。
3. 某一字段没有有效参考值时，只让该字段使用 100% 标准；其他有效字段继续使用参考值。

“附近”指区块中心之间的画布距离不超过 1200 个画布单位。候选先按中心距离升序排列，距离相同时按节点 ID 字典序排列，最多取前三个，不因当前镜头缩放而改变。AI 不修改参考区块，只读取尺寸。不同内容类型分别匹配：

- 文本参考文本区块。
- 图片参考图片区块。
- 文件参考文件区块。
- 链接参考链接区块。

字段有效性和中位数规则：

- 宽度、高度和字号必须是有限正数；无效或缺失值不参与该字段计算。
- 缺失 `contentScale` 的旧节点按 `1` 参与计算；非有限、非正数或超出 `0.1667–10` 的值也按 `1` 处理。
- 一个有效候选直接使用该值。
- 两个有效候选使用两者的算术平均值。
- 三个有效候选排序后使用中间值。
- 所有 AI 尺寸结果使用 `round4`。

如果无法取得有效参考值，则回退到当前 100% 标准：

- 默认文本观感字号对应画布字号 15px。
- 链接和文件卡片为 320×112。
- 图片卡片为 320×220。
- 文本区块继续使用文本长度估算尺寸。
- 内部内容尺度 `contentScale` 为 `1`。

## 9. 模块边界

### 9.1 纯换算模块

新增独立的视角尺寸策略模块，负责：

- 把缩放倍率限制为 0.10–6.00。
- 屏幕尺寸与画布尺寸互转。
- 持久化四位小数和显示两位小数的分别归一化。
- 批量换算宽高、字号、间距和级联偏移。
- 计算并验证派生的 `contentScale`，将结果限制在 `0.1667–10`。
- 拒绝非有限、零或负尺寸。

该模块不读取 React 状态、不写数据库，也不处理手势。

### 9.2 画布事件编排

`canvas-editor.tsx` 负责：

- 在绘制、粘贴、系统拖入、笔记选择器确认或图片选择器打开时捕获视角倍率；完整画布导入不捕获视角倍率。
- 把操作倍率传给纯换算模块。
- 在一次历史事务中提交换算后的节点。
- 操作取消时丢弃快照，不产生节点或历史记录。

### 9.3 内容摄取

`content-ingest.ts` 继续负责识别文本、链接、图片和文件，但其草稿尺寸明确为屏幕预设尺寸。实际画布尺寸只在编辑器提交草稿时换算，避免摄取模块依赖 React Flow。

### 9.4 样式菜单

`canvas-node-style-menu.tsx` 接收：

- 持久化的画布实际字号。
- 打开菜单时捕获的编辑会话倍率。

它显示屏幕观感字号，并把用户修改后的观感值交回编辑器换算和提交。

### 9.5 数据类型

`src/types/canvas.ts` 做两项向后兼容扩展：

- 把 `fontSize` 放宽为有限数字。
- 增加可选的 `contentScale` 有限数字，用于渲染卡片图标、内边距和图文间距。新建的文本、笔记、链接、文件、图片及其他现有内容卡片必须写入该值；自由画笔、分组和关系线不使用该字段。字段保持可选仅用于兼容旧数据。

旧节点缺少 `contentScale` 时按 `1` 处理。已存在但非有限、非正数或超出 `0.1667–10` 的值也仅在渲染时按 `1` 处理，不在载入阶段重写文档。区块宽高和图片尺寸继续使用现有节点尺寸字段，不需要数据库迁移，也不保存原始视角快照。

## 10. 状态与撤销

- 每次新建一批粘贴或拖入内容只建立一次历史快照。
- 字号编辑会话只在第一次实际修改前建立一次历史快照。
- 修改多个选中区块属于同一次历史事务。
- 用户取消绘制、取消导入或关闭未修改的样式菜单，不产生空历史记录。
- 画布视角仍按现有方式独立持久化；缩放视角本身不修改节点历史。
- 撤销和重做恢复已经换算完成的实际尺寸，不重新读取当前缩放倍率。

## 11. 异常与回退

- 打开文档时，持久化视角的无效值严格按 4.1 节处理：无效 `x` 或 `y` 使用 `0`，缺失、非有限或小于等于零的 `zoom` 使用 `0.65`，有限正数的 `zoom` 限制到 0.10–6.00；载入阶段不读取上一个文档或上一次会话的倍率。
- 运行中的创建或编辑操作捕获快照时，有限正数的实时 `zoom` 限制到 0.10–6.00；实时 `zoom` 无效时使用当前文档最近一次有效的内存倍率，没有记录时使用 `0.65`。实时 `x` 或 `y` 无效时分别使用当前文档最近一次有效的内存坐标，没有记录时使用 `0`。
- `containerLeft` 或 `containerTop` 无法取得有限值时取消本次依赖屏幕坐标的操作，不创建节点、不修改尺寸且不建立历史。
- 换算结果不是有限数、为零或为负数时，取消该尺寸修改并保留原值。
- 粘贴文本估算失败时，使用 320×112px 的屏幕预设后再换算。
- 图片元数据读取失败时，使用 320×220px 的屏幕预设后再换算。
- 批量摄取必须按项目独立结算，使用等价于 `Promise.allSettled` 的语义；单个文件失败不阻塞其他有效项目。
- 至少一个项目成功时，只为成功节点建立一次历史快照并一次性加入画布；全部失败时不建立历史。
- 每个项目记录本次操作中新建的资源路径。项目在节点提交前失败时删除其新建资源；整个批次在节点提交前失败时删除该批次所有新建资源，避免孤立文件。
- 清理失败只记录经过脱敏的诊断，不把不存在的节点加入画布，也不影响其他成功节点。
- 结束提示显示成功和失败数量；失败项沿用现有错误提示，不输出文件内容或敏感配置。
- 任何失败都不得留下只有外框、没有有效数据的半成品区块。

## 12. 可访问性与交互反馈

- 缩放控件显示 10%–600% 的当前百分比。
- 缩放滑块必须支持键盘方向键调整，步长为 5%。
- 字号数值输入提供明确的“屏幕字号”标签，避免用户误认为它是画布实际字号。
- 字号控件的辅助说明可显示换算结果，例如“当前 25%：屏幕 15px，画布 60px”。
- 不新增常驻信息面板；换算说明只出现在样式菜单或短提示中。
- 极端缩放下的创建反馈仍以屏幕像素呈现，确保选框、拖动轮廓和命中区域可见。

## 13. 验证设计

### 13.1 纯函数测试

对 10%、25%、65%、100%、200% 和 600% 验证：

- `300 / Z` 的区块宽度结果。
- `15 / Z` 的画布字号结果。
- 画布尺寸乘以 `Z` 后恢复屏幕观感尺寸。
- 持久化结果保留四位小数，显示结果保留两位小数，并消除 `-0`。
- 非有限、零、负数和越界倍率的回退。
- 正向和反向换算后的屏幕误差不超过 0.01px；必须覆盖 `S=8.02、Z=6` 的极端精度案例。

### 13.2 创建入口测试

- 任何倍率下单击和单轴拖动都不创建区块。
- 二维拖动创建的屏幕观感宽高与用户拖动一致。
- 创建中途改变缩放或平移，位置和尺寸仍使用按下时的完整视角快照。
- 异步文件持久化期间改变缩放或平移，节点仍使用 drop、paste 或文件选择开始时的位置。
- 纯文本、链接、图片和文件草稿均按粘贴或拖入时倍率换算。
- `text/uri-list`、HTML 单链接和纯文本链接按入口矩阵创建链接卡片。
- 通过普通 paste 或 drop 进入的 JSON、项目文件或 Mermaid 内容创建普通文件或文本节点并执行视角换算，不触发完整画布替换；只有显式完整画布导入命令保留源尺寸。
- 多项拖入按实体区块碰撞规格形成 6px 屏幕间距的无重叠纵向列，并在不同倍率下保持一致观感。
- 批次部分失败时只创建成功节点、只写入一次历史并清理失败项目的新资源。
- 批次全部失败时不创建节点、不写历史并清理本批次资源。
- 复制已有节点不会被当前倍率重新缩放。

### 13.3 编辑测试

- 打开字号菜单显示 `实际字号 × 会话倍率`。
- 公式结果超出 8–96px 时仍显示真实值且不自动改写；只有用户提交的字号新值受 8–96px 限制。
- 仅打开和关闭菜单不改变数据。
- 修改为 15px 时保存 `15 / 会话倍率`。
- 菜单打开后改变画布倍率，当前编辑会话的换算基准不跳变。
- 多选混合字号正确显示并能一次应用统一观感字号。
- 字号修改只产生一个撤销检查点。
- 文本、文件和链接外框调整使用开始时快照；成功只产生一个撤销检查点。
- 图片调整默认保持纵横比；pointer cancel、失焦和捕获丢失恢复会话前尺寸且不产生历史。
- 调整外框不改变已有内部字号、图片内容尺度或 `contentScale`。
- 分别验证文档载入与运行时快照的无效视角回退；运行时没有有效容器坐标时取消操作且不产生历史。

### 13.4 AI 尺度测试

- 有明确目标区块时匹配目标同类尺寸。
- 明确目标类型不匹配时忽略该目标的尺度并进入附近同类候选流程。
- 分别覆盖一个、两个和三个候选的直接值、算术平均值和中间值规则。
- 距离相同的候选按节点 ID 稳定排序。
- 字段无效时只回退该字段；旧节点缺失或含非法 `contentScale` 时按 `1`。
- 没有附近同类区块时回退到 100% 标准。
- 改变镜头倍率不会改变相同 AI 操作的创建尺寸。
- AI 读取参考尺寸时不修改任何已有区块。

### 13.5 集成验证

- Canvas 测试、foundation 合约、TypeScript、生产构建和锁定 Cargo 检查通过。
- 新画布首次打开为 65%，缩放范围为 10%–600%。
- 已有画布保存的视角不被覆盖。
- Windows 安装版中，绘制、粘贴、拖入、字号修改、撤销和重做行为一致。
- 现有点阵、关系线、右键手势、中键平移和底部 AI 对话不回归。

## 14. 验收标准

1. 新画布默认显示 65% 视角，用户可在 10%–600% 范围缩放。
2. 用户直接创建的区块和内容满足 `画布尺寸 = 屏幕尺寸 ÷ 操作开始倍率`。
3. 创建过程中改变视角不会改变当前创建结果。
4. 字号菜单显示屏幕观感字号，修改后保存对应的画布实际字号。
5. 通过粘贴、系统拖入、笔记选择器和图片选择器新建的内容采用统一换算；完整画布导入保留原文档尺寸。
6. 复制、撤销、重做和旧数据载入不重复换算。
7. AI 创建尺寸来自目标、附近同类内容或 100% 标准，不来自当前镜头倍率。
8. 所有尺寸修改安全进入历史记录，不产生空历史或半成品区块。
9. 现有画布数据无需迁移，用户内容和区块位置不被自动重写。
10. 自动化验证和 Windows 安装版集成验证全部通过。

## 15. 后续补充方式

本 v1 规格没有未决值或实现占位。用户后续提出的新要求将作为明确的规格修订写入 v2 或后续版本，并重新检查与当前公式、入口矩阵、历史事务和兼容规则是否冲突。任何修订都必须继续满足“操作开始时只捕获一次完整视角快照、已有内容不因视角变化被自动改写”两条核心约束。
