# 画布（Huabu）实施路线图

> 本路线图把产品规格拆成可独立构建、测试和验收的实施计划。每一阶段完成后，基于当时的本地源码再编写下一份逐步计划，避免在上游源码尚未导入时猜测文件路径。

## 阶段顺序

| 阶段 | 独立交付结果 | 依赖 | 对应规格 |
|---|---|---|---|
| 0. 源码与 Windows 基线 | 固定 NoteGen 上游提交、可编译的 Huabu Windows 应用、GPL 归属和 Windows CI | 无 | 3、14、17 |
| 1. 画布优先产品壳 | 启动即进入全画布界面，移除导出入口和常驻信息面板 | 阶段 0 | 8、9、10 |
| 2. AI 权限与事务 | 管理/编辑模式、权限网关、幽灵预览、原子提交和整体回退 | 阶段 1 | 5、6 |
| 3. AI 覆盖层 | 独立 AI 标签、AI 关系、置信度、理由、抑制记录和显示开关 | 阶段 2 | 7、12 |
| 4. 记忆检索与导航 | 节点级索引锚点、混合检索、证据卡、镜头定位和返回原视图 | 阶段 3 | 4、11 |
| 5. 对话坞与动效 | 底部 AI 对话坞、按需结果卡、管理/编辑状态和呼吸动效 | 阶段 2、4 | 9 |
| 6. 线性浏览与保存视图 | 关联阅读、时间/相关度排序、一层/两层关系和保存的筛选视图 | 阶段 3、4 | 10 |
| 7. Windows 安全与恢复 | Credential Manager、敏感内容脱敏、事务恢复、备份轮换和只读恢复 | 阶段 2、4 | 13、14、15 |
| 8. MVP 验收 | 离线、崩溃、权限绕过、大画布和 Windows 安装包完整验证 | 阶段 0–7 | 16、17、18 |

## 阶段门槛

每个阶段必须满足以下条件后才能进入下一阶段：

1. 新行为有自动化测试或可重复的验证脚本。
2. Windows 前端构建和 Rust `cargo check` 通过。
3. 对应数据迁移可回退或可从原始数据重建。
4. 没有把未来阶段的功能提前塞入当前阶段。
5. 提交保持小而可审查，不混入无关重构。
