# zeroxB 永久画布、文本侧栏与 AI HUD 需求翻译 v1

## 问题观察

当前进入画布模式后，应用绕过原有三栏布局，只保留中央编辑区域与底部 AI 输入框。完整聊天消息、会话历史、左侧文件/笔记/画布浏览和右侧编辑面板因此不可见，造成画布像一个临时窗口而不是永久工作台。

## 用户影响

- 用户能输入 AI 问题，但看不到当前聊天记录。
- 用户无法在画布保持可见的同时正常浏览和编辑文本页。
- 侧栏原有功能在画布模式下消失，无法自然地把笔记拖入画布。
- TTS 能力需要保留，但缺少与 HUD 对话状态一致的轻量交互。

## 已确认预期行为

1. 画布永久挂载并作为首页中央主工作区。
2. 左侧栏保留文件、文本笔记和画布三个栏目，可折叠为 48px 图标栏；展开宽度约 320px，状态持久化。
3. 笔记悬停 400ms 显示只读预览；单击在右侧打开完整文本面板；右侧保留多标签编辑能力。
4. 笔记条目拖入画布创建关联节点，源正文只存在于文本页；同一笔记可在一个画布中有多个引用。
5. 源笔记更新时，所有引用自动刷新标题、摘要和更新时间；删除源笔记后引用进入可修复的缺失状态。
6. 全局会话保留现有数据库和历史能力；每条消息记录来源画布，发送时 RAG 只读取当前画布。
7. 当前会话文字以屏幕空间 HUD 跟随底部对话坞，不跟随画布平移或缩放。
8. 收缩 HUD 显示最近一轮原文截断，展开后显示完整可滚动记录；历史按钮打开小型可搜索浮层。
9. 普通文字提问手动朗读；麦克风语音提问的最终 AI 回答自动朗读，用户再次说话时停止朗读。

## 范围与非目标

本任务只设计 Windows 桌面端应用壳层、文本关联和 AI HUD。复用现有聊天数据库、RAG、TTS、STT、编辑器、文件和画布能力，不新建平行数据层；不把 HUD 消息写入画布、不复制文本正文到节点、不改变既有右键/中键/关系/撤销语义。

## 验收标准

- 画布模式下中央画布始终挂载，切换侧栏、文本面板和聊天会话不会丢失画布状态。
- 左侧栏可折叠、可恢复，三类原有功能可用。
- 预览、点击打开、拖动引用三种笔记手势不互相误触。
- 右侧文本多标签保持，画布节点与源文本双向定位但正文单一来源。
- 全局会话可搜索、切换、删除和新建；消息来源画布正确显示。
- HUD 收缩/展开、滚动、加载、切换会话和 TTS/STT 状态在画布上清晰可见但不遮挡核心操作。
- 旧功能、错误恢复、键盘操作和 Windows 安装版验证不回归。

## 用户视角补充

- 预览必须允许光标从侧栏进入预览层，否则用户无法读完内容。
- 右侧文本面板关闭后保留打开标签，避免反复定位文件。
- 全局会话跨画布时必须显示来源画布，否则用户会误把不同画布的记忆混为一谈。
- HUD 不能使用覆盖整块画布的厚重卡片；摘要和历史只在需要时出现。
- TTS 流式输出完成后再朗读，避免断句和重复播放。

## 验证计划

- 壳层挂载、面板折叠、右侧文本标签和画布保持测试。
- 笔记悬停预览、拖入引用、多引用同步和缺失来源恢复测试。
- 全局会话来源画布、当前画布检索、历史浮层和切换保护测试。
- HUD 收缩/展开、滚动、键盘 Esc、加载和 TTS/STT 流程测试。
- TypeScript、生产构建、Tauri/Cargo、NSIS 安装与 Windows 实机回归测试。
